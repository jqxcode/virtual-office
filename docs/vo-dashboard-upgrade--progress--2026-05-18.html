Driving blind at 100 mph

以时速160公里盲目驾驶 — 没有仪表盘的自主代理系统

We run 9+ autonomous AI agents 24/7 on Task Scheduler, spending real money on Claude API tokens. But we are completely blind to their behavior. Running autonomous agents without observability is like driving a car without a dashboard — you don't know your speed, fuel level, engine temperature, or which warning lights should be on. The car is moving, but you have no idea whether it is heading toward a cliff or running flawlessly. Every dollar spent is invisible. Every quality degradation is silent. Every failure requires reactive log-digging to discover. 我们在 Task Scheduler 上全天候运行 9 个以上的自主 AI 代理，花费真实的 Claude API 费用。但我们对其行为完全不知情。在没有可观测性的情况下运行自主代理，就像在没有仪表盘的情况下驾车 — 你不知道车速、油量、引擎温度，也不知道哪些警示灯应该亮起。车在走，但你不知道它是在驶向悬崖还是运转正常。每一笔支出不可见，每一次质量退化无声无息，每一次故障都要靠事后翻日志才能发现。

Cost Record Schema / 成本数据结构
// Per-job cost record appended to audit JSONL
{
  "jobName":              string,   // e.g. "TODO-sprint-progress"
  "agent":               string,   // e.g. "auditor"
  "timestamp":           ISO8601,  // run start time
  "inputTokens":         number,
  "outputTokens":        number,
  "cacheCreationTokens": number,
  "cacheReadTokens":     number,
  "costUSD":             number,   // total_cost_usd from CLI
  "durationMs":          number,
  "model":               string,   // e.g. "claude-sonnet-4-6"
  "contextUsedPct":      number    // (input+output)/contextWindow*100
}
Technical Details / 技术细节
  • The JSON output from claude -p --output-format json returns a result object with result (text output), total_cost_usd, usage (token breakdown), and modelUsage (per-model stats with contextWindow). The runner parses JSON, extracts text for file saving, and stores cost separately. CLI JSON 输出包含 result（文本）、total_cost_usd、usage（token 细分）、modelUsage（含 contextWindow）。Runner 解析 JSON，文本用于保存，成本数据单独存储。
  • contextUsedPct = (inputTokens + outputTokens) / contextWindow × 100. This controls the context badge color on agent office icons. 上下文使用率 = (输入 token + 输出 token) / contextWindow × 100，控制代理图标上的上下文徽章颜色。
    Why lower is better / 为什么越低越好

    The context window is the model's working memory. Like an engine temperature gauge, what matters is staying below the red line — not maximizing or minimizing. Context window 是模型的"工作记忆"。和水温表一样，关键是不要过热——不是追求越高越好或越低越好。

    <70% (Green) Healthy — model remembers all instructions, tool results, file contents. Output quality normal.健康——模型记得所有指令、工具返回、文件内容，输出质量正常。
    70-90% (Yellow) Warning — approaching limit, model may start compacting (compressing early context), losing some earlier information.警告——接近上限，模型可能开始压缩早期上下文，丢失部分早期信息。
    ≥90% (Red) Danger — model forced to aggressively compact, forgets earlier instructions and tool results. May skip tasks, repeat work, or ignore constraints. Output quality unreliable.危险——模型被迫大量压缩，忘掉早期指令和工具结果。可能漏做事、重复做事、忽略约束。输出质量不可信。

    Low usage = agent completed task efficiently without filling context. High usage = possible prompt loop, too many files read, or task inherently too complex for one session. A red badge means: review the output manually before trusting it. 低使用率 = agent 高效完成任务。高使用率 = 可能死循环、读了太多文件、或任务过于复杂。红色徽章意味着：在信任输出之前必须人工审查。

Rationale / 理由

Audit JSONL files are already append-only and per-agent. Adding cost fields is a backward-compatible schema extension. The server reads these files with an exclusive lock to prevent race conditions with concurrent runner writes. This is the minimal schema change with maximum reuse of existing infrastructure.

审计 JSONL 文件已是追加写入、按代理分组。添加成本字段是向后兼容的结构扩展。服务器使用独占锁读取这些文件，防止与并发 Runner 写入发生竞争。这是对现有基础设施最大复用的最小结构变更。

D6
Anomaly Detection Algorithm
异常检测算法选择
▼
Decision / 决策

Flag a job run as anomalous if its cost exceeds 2× the rolling average of all previous runs for that job. Implemented in server.ps1 as part of the /api/costs response. No ML, no external service, no configuration required.

若某任务运行成本超过该任务所有历史运行的滚动均值的 2 倍，则标记为异常。在 server.ps1 中实现，作为 /api/costs 响应的一部分。无需 ML、外部服务或额外配置。

Options Evaluated / 评估的方案
AlgorithmComplexityEffectiveness for Cost SpikesVerdict
2× rolling averageO(n) read, statelessHigh — catches prompt loops, tool explosionsChosen
Z-score (3-sigma)Requires stddev computationHigh, but overkill for sparse dataDeferred
Fixed threshold (e.g. >$1)TrivialLow — expensive jobs would always alertRejected
ML anomaly modelExternal dependency + training dataOverkill for <30 jobsRejected
Rationale / 理由

The 2× rolling average is the simplest algorithm that reliably catches the most common anomaly patterns: prompt death loops (cost 10-100x normal), tool call explosions, and model upgrade surprises. It is stateless — the server recomputes it each time from the JSONL log, so no separate state file is needed. The threshold is job-relative, so expensive jobs (like sprint reports) and cheap jobs (like memory consolidation) each have their own baseline.

2 倍滚动均值是能可靠捕捉最常见异常模式的最简算法：prompt 死循环（成本 10-100 倍）、工具调用爆炸、模型升级意外。无状态，服务器每次从 JSONL 日志重新计算，无需额外状态文件。阈值相对于每个任务，因此昂贵任务（如冲刺报告）和便宜任务（如内存整合）各自有独立基线。

Rationale / 理由

The VO portal is a dark-themed, self-contained HTML dashboard with its own design system established from the linear-design-system-prettify session. The Dreamer agent's cross-reference confirmed the design system work is completed and the vo-theme-0.2.0 tokens cover all needed primitives: color, spacing, radius, shadow, typography. Introducing an external library would create a dependency, widen the attack surface, and conflict with the existing dark theme tokens. The feedback rule feedback_adopt_design_systems.md requires diffing external systems against working values before adopting — after diffing, no gap was found that warranted adoption.

VO 控制台是拥有自己设计系统的深色主题独立 HTML 仪表盘，设计系统已在 linear-design-system-prettify 阶段完成。Dreamer 代理确认 vo-theme-0.2.0 token 覆盖所有必要原语。引入外部库会增加依赖、扩大攻击面，并与现有深色主题 token 冲突。对比后未发现值得采用的差距。
